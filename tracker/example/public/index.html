RevScope · tracker.js demo

Example pages

Run pnpm start (or node server.js) from tracker/example, and keep the revscope backend listening on localhost:4320. Pages install the documented queue stub for project example (loads http://localhost:4320/example.js) with hostname: "example.com" (required on loopback). Watch DevTools → Network for POSTs to /example (batched after the first pageview).

Simulated external referrer: open http://127.0.0.1:3447/ first, then click through to landing.html (different port → cross-origin document.referrer).

Pageviews & navigation

  • Landing + referrer / UTMs First-hit attribution; best entered via port 3447.
  • History API SPA pushState / popstate pageviews + engagement flush.
  • Hash SPA mode: "hash" / data-mode="hash".
  • Multi-page navigation Full reloads across pages in one session.
  • Path rewriter config.pathRewriter normalizes dynamic paths.
  • Custom hostname data-hostname / stub config.hostname.

Filtering & params

  • Ignored paths ignorePages / data-ignore-pages.
  • UTM, click IDs & include-params Allowlist + built-in campaign / ad click IDs.

Events

  • JavaScript dispatch API Call dispatch with event metadata, callback, or beacon options.
  • Declarative HTML events data-revscope-click / visible / beacon / metadata + named anchors.
  • Outbound & mailto clicks Automatic revscope-outbound-click via sendBeacon.
  • Pre-load dispatch queue Queue commands before the script finishes loading.

Metadata, consent & engagement

  • Static metadata config.metadata object on pageviews.
  • Metadata function config.metadata(eventContext) callback.
  • Consent and tracking choices set_consent with granted, denied, or disabled.
  • Scroll & engagement Tall page for scroll depth; tab hide / leave for engagement.

Tip: after the first pageview, subsequent hits are batched (up to 30s or 20 items). Use beacon: true or a callback to flush immediately when testing events.
